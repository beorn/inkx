# [x] CI: km-core build-info.gen.ts missing in fuzz workflow (and any vitest run from clean install) @km/infra #bug #P2

blocks:: [[@km/infra/guardrails]]

Surfaced by N1 (@km/infra/continuous-fuzz) CI run 24980853272 — every fuzz test crashes at module load with:

    Cannot find module './build-info.gen.ts' imported from .../packages/@km/_orphan/core/src/index.ts

## Why
- packages/@km/_orphan/core/src/index.ts:42 imports from ./build-info.gen.ts
- The file is generated by scripts/generate-build-info.ts via package.json's build:info script
- build:info runs as prebuild (chained from bun run build), NOT as postinstall
- bun install --frozen-lockfile alone does not generate the file
- Any vitest run from a clean checkout (CI, fresh worktree, fresh clone) fails until build:info runs
- Local dev is unaffected because the file is generated once and persists

## Blast radius
- N1 fuzz workflow: every nightly run goes red with the same root error excerpt; bead-creation script is idempotent so no spam, but the fuzz signal is dead until this is fixed
- Any future CI workflow that runs vitest from a clean install
- Fresh git clones / worktree-create before first build

## Fix options (pick one — TBD)
1. Add postinstall hook to package.json: `\"postinstall\": \"bun run build:info\"`
   - Simple, deterministic, runs everywhere bun install runs
   - Cost: every install regenerates (cheap, ~50ms)
2. Make the import optional with a runtime fallback in @km/_orphan/core
   - More resilient but adds branching + non-frozen behavior
3. Generate on demand at first import via a setup file
   - Clever but introduces import-time side effects
4. CI-only: add `bun run build:info` to .github/workflows/fuzz.yml after install
   - Targeted fix; doesn't help fresh worktrees
   - Need to repeat for every workflow that runs vitest

Recommend: option 1 (postinstall). Cheapest, most universal.
