# [x] batch-refactor: UTF-8 offset bug in ripgrep backend @km/_orphan #bug #P2 @claude:5f8fa618

The ripgrep backend calculates byte offsets using character length (lines[i].length) but UTF-8 multi-byte characters like → cause the offset to be wrong. Example: line with → character generates wrong replacement 'ult/P' instead of 'repo'. File: vendor/beorn-claude-tools/plugins/batch/tools/lib/backends/ripgrep/search.ts
