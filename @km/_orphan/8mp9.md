# [x] TUI: Slow rendering when cursoring around on boards with many items @km/_orphan #bug #P1

## Problem

When cursoring around on boards with many items, rendering is very slow. Every cursor movement triggers a full re-render of the entire board, even though only the selection state changed.

## Analysis

**Current flow on cursor move (e.g., pressing "j"):**
1. `useInput` captures key → `dispatchBoard({ type: "CURSOR_MOVE" })`
2. Board reducer returns new BoardState with updated cursor path
3. React detects state change → **full component tree re-renders**
4. All visible Column, Card, and TreeNode components re-render
5. Each TreeNode recalculates: getNodeStyle(), renderRich(), formatInfoSuffix()

**For 60 visible cards:** 60× style calculations + 60× rich text parsing per keystroke.

**What is NOT memoized:**
- Column component - no React.memo
- Card component - no React.memo  
- TreeNode component - no React.memo
- TreeNode internal calculations - no useMemo

---

## Iteration 1: Add React.memo to leaf components

**Approach:** Wrap Card and TreeNode in React.memo with shallow prop comparison.

```tsx
// TreeNode.tsx
export const TreeNode = React.memo(function TreeNode(props) {
  // existing implementation
});

// CardColumn.tsx  
const Card = React.memo(function Card(props) {
  // existing implementation
});
```

**Pros:**
- Simple to implement
- Standard React optimization pattern
- Skip re-renders when props unchanged

**Cons:**
- Props include `isSelected` which changes for 2 items on each cursor move
- May not help much if parent re-renders force new object references
- Need to ensure stable prop references (callbacks, style objects)

**Verdict:** Necessary but insufficient. Moving cursor still re-renders 2 cards minimum, and if props are unstable references, memo is defeated.

---

## Iteration 2: Separate selection state from node data

**Approach:** Split props so node content and selection are separate concerns.

```tsx
// Card receives stable node data, reads selection from context
const Card = React.memo(function Card({ nodeId, columnIndex }) {
  const isSelected = useSelector(state => 
    state.cursor.path[0] === columnIndex && 
    state.cursor.itemId === nodeId
  );
  // ...
});
```

**Pros:**
- Node data props become stable across cursor moves
- Only the 2 affected cards re-render (old selected, new selected)
- Pattern works well with selectors

**Cons:**
- Requires adding context/selector infrastructure
- More invasive change to component architecture
- Selection state is already in BoardState, need to wire context

**Verdict:** Better but adds complexity. Selection changes still trigger re-renders of the affected cards.

---

## Iteration 3: Memoize expensive TreeNode calculations

**Approach:** Keep current architecture but heavily memoize internal calculations.

```tsx
// TreeNode.tsx
function TreeNode({ node, isSelected, ... }) {
  // Memoize style calculation - only recalc when node or selection changes
  const nodeStyle = useMemo(
    () => getNodeStyle(node, isSelected, ctx),
    [node.id, node.status, isSelected, ctx.colorScheme]
  );
  
  // Memoize rich text rendering - only recalc when content changes
  const richContent = useMemo(
    () => renderRich(node.content, maxWidth),
    [node.content, maxWidth]
  );
  
  // Memoize info suffix - only recalc when metadata changes
  const infoSuffix = useMemo(
    () => formatInfoSuffix(node),
    [node.due, node.priority, node.tags?.join()]
  );
}
```

**Pros:**
- Works within current architecture
- Calculations only run when their specific inputs change
- Even if Card re-renders, TreeNode work is cached
- Measurable improvement without structural changes

**Cons:**
- Cards still technically re-render (React reconciliation cost)
- Memory overhead of caching
- Need to get dependency arrays right

**Verdict:** Good incremental improvement, low risk. Should combine with memo.

---

## Iteration 4: FINAL - Layered optimization strategy

**Approach:** Combine iterations 1+3, defer iteration 2 complexity.

### Phase 1: Memoize TreeNode internals (Iteration 3)
- Add useMemo to getNodeStyle, renderRich, formatInfoSuffix in TreeNode
- These are the actual expensive operations

### Phase 2: Add React.memo to Card and TreeNode (Iteration 1)
- Wrap Card in React.memo
- Wrap TreeNode in React.memo with custom comparison:
  ```tsx
  export const TreeNode = React.memo(TreeNodeImpl, (prev, next) => {
    return prev.node.id === next.node.id &&
           prev.isSelected === next.isSelected &&
           prev.node.content === next.node.content &&
           prev.node.status === next.node.status;
  });
  ```

### Phase 3: Stabilize callback props
- Use useCallback for event handlers passed to Card/TreeNode
- Ensure style objects are stable (useMemo or move outside component)

### Expected Result
- Cursor move: Only 2 TreeNodes recalculate (old/new selection)
- Other 58 visible cards: memo prevents re-render entirely
- ~30x improvement in render work per keystroke
