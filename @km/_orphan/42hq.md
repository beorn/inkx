# [x] Remove unnecessary setTimeout(50) delays from Board.tsx mutations @km/_orphan #task #P2

## Summary

The TUI Board.tsx uses `setTimeout(..., 50)` after store mutations (delete, move, status change, etc.) to delay rebuilding board state. Investigation shows these delays are **unnecessary** because all store mutations are synchronous.

## Findings

### Store mutations are synchronous:
- `deleteNode()` - uses `emit()` with `appendFileSync()` (sync)
- `moveNode()` - uses `emit()` with `appendFileSync()` (sync)  
- `updateNode()` - uses `emit()` with `appendFileSync()` (sync)
- `buildBoardState()` - just reads from database (sync)

### Two categories of setTimeout(50):

**NECESSARY (2 instances)** - Fullscreen-ink alternate buffer race condition:
- Line 1767: Startup dimension polling
- Line 1778: Startup immediate dimensions
- Documented in docs/dev/ink-patterns.md - DO NOT REMOVE

**UNNECESSARY (9 instances)** - Post-mutation refreshes that add 50ms latency:
- Line 696: After status change
- Line 720: After delete  
- Line 1261: After status change in detail pane
- Line 1292: After priority set
- Line 1331: After project move
- Line 2038: After move up/down
- Line 2113: After move left/right
- Line 2194: After move to index
- Line 2270: After indent
- Line 2326: After outdent

## Impact

Every user action (toggle status, move card, delete, etc.) has an unnecessary 50ms delay. Removing these will make the TUI feel more responsive.

## Solution

Replace the setTimeout pattern with immediate synchronous refresh:

```typescript
// Before (unnecessary delay):
deleteNode(nodeToDelete);
setTimeout(() => {
  const newState = buildBoardState(state.rootId) || initBoardState();
  setState(newState);
}, 50);

// After (immediate refresh):
deleteNode(nodeToDelete);
const newState = buildBoardState(state.rootId) || initBoardState();
setState(newState);
```
