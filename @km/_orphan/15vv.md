# [x] CLI negation filter -status:done interpreted as option flag @km/_orphan #bug #P2

The command `km tasks --all -status:done` fails because the leading `-` in `-status:done` is interpreted as a CLI option flag rather than a query filter.

## Reproduction
```bash
bun km tasks --all "-status:done" --json
# error: unknown option '-tatus:done'
```

## Expected
The `-status:done` should be treated as a negation filter in the query language.

## Suggested Fix
Either:
1. Use `--` separator: `km tasks --all -- -status:done`
2. Parse query filters before option parsing
3. Document a different negation syntax (e.g., `not:status:done` or `!status:done`)
