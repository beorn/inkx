# [x] TUI2 Visual Parity with TUI1 @km/_orphan #feature #P2

Systematically verify that TUI2 (OpenTUI) styling matches TUI1 (Ink) for all screens.

## Background

As part of the OpenTUI migration, we need to ensure visual consistency between TUI1 and TUI2. This bead tracks the systematic comparison and fixing of styling differences.

## Scope

### Screens to Compare

1. **List View**
   - Task rows with checkboxes
   - Selected item highlighting
   - Folded/collapsed indicators

2. **Columns View**
   - Column headers with task counts
   - Cards within columns
   - Selection within columns

3. **Tabs View**
   - Tab bar at top
   - Content area

4. **Overlays/Modals**
   - Search mode (`/`)
   - Help mode (`?`)
   - New item dialog (`n`)
   - Project picker (`p`)
   - Detail pane (`i`)

5. **Status Elements**
   - Status bar at bottom
   - Path breadcrumb
   - Error messages

### Styling Elements to Check

Per [specs/@km/design-system/md](specs/@km/design-system/md):

| Element | Expected Style |
|---------|----------------|
| Selection | cyan bg + black fg (NEVER blue/white) |
| Headers (selected) | yellow |
| Headers (unselected) | yellowBright + dim |
| Input cursor | inverse |
| Task todo | ○ |
| Task done | ✓ (green) |
| Folded indicator | (+N) |

## Test Approach

1. Create side-by-side screenshots:
   ```bash
   # TUI1
   ttyd -W -p 7681 bun km view -r /tmp/test @next.md &
   HEADLESS=true bun x playwright screenshot http://localhost:7681 /tmp/tui1.png
   
   # TUI2
   ttyd -W -p 7681 bun km view --tui2 -r /tmp/test @next.md &
   HEADLESS=true bun x playwright screenshot http://localhost:7681 /tmp/tui2.png
   ```

2. Compare screenshots for each screen/mode
3. Document differences
4. Fix TUI2 to match TUI1 styling

## Acceptance Criteria

- [ ] All view modes match visually
- [ ] All overlays/modals match
- [ ] Selection colors match design system
- [ ] Task status icons match
- [ ] No visual regressions introduced
