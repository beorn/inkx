# [x] Simplify view.ts: remove engine option, initializeState callback, use Disposable spinner @km/_orphan #task #P2

## Current Problems

1. `engine` option exposed to users but should be internal-only
2. `initializeState` callback pattern passes state loading into TUI unnecessarily
3. Separate interactive/non-interactive code paths when they could be unified
4. `runWithProgress` callback indirection when generator can be consumed directly
5. Manual spinner.stop() instead of Disposable pattern

## Proposed Changes

1. Remove `--tui` CLI option, keep engine as internal constant
2. Load state BEFORE runBoard, pass loaded state to board
3. Unify code paths - board receives state and `interactive` flag
4. Delete `runWithProgress`, consume `ensureState` generator directly
5. Make Spinner implement `Symbol.dispose` for auto-cleanup

## Result

```typescript
{
  using spinner = new Spinner({ text: 'Loading vault...' });
  spinner.start();
  
  for (const info of ensureState(vaultRoot, false)) {
    spinner.text = formatProgress(info);
  }
}
// spinner auto-stops

await runBoard(nodeRef, vaultRoot, {
  state,  // always provided
  interactive: options.interactive !== false,
  viewMode,
  watch: watchEnabled,
});
```

Board becomes simpler - no loading state, always has data, more testable.
