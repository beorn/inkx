# [x] Command system needs modal context for keybindings @km/_orphan #task #P1

When modals are open (help dialog, project picker, new item dialog), keybindings should be different. Currently the command system has a `KeybindingContext` with a `mode` field (normal/move/search/input) but:

1. Modal state isn't properly represented - `inInputMode` is set when dialogs are open but this doesn't fully capture the keybinding requirements
2. The `modes` field on keybindings is underutilized - only move mode uses it for Enter/Escape
3. Help overlay should block all keys except Escape/q/?

Research needed:
- How should modal contexts layer? (help overlay > project picker > normal)
- Should modals have their own keybinding sets or just filter the main set?
- How do other TUI apps handle this? (vim modes, emacs transient states)
- Current KeybindingContext has: mode, hasSelection, isInDetailPane, isInOutlineMode, currentNode
- Should add: activeModal, modalStack, allowedKeysInModal

Implementation options:
1. Modal-specific keybinding sets that override defaults
2. `when` conditions on keybindings that check modal state
3. Early return in key handler before command system for modal-specific handling
4. Proper modal context in KeybindingContext with exhaustive handling
