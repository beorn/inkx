# [x] Storage: Top-level folders have NULL parent_id, not connected to tree @km/_orphan #bug #P1

Top-level folders (inbox, journals, projects, areas, etc.) were created with parent_id = NULL instead of parent_id = '.' (the repo root). This caused them to not appear as children of the root in the TUI, making them unreachable via navigation.

**Root cause**: The discovery.ts query to find the repo root node used:
```sql
SELECT id FROM nodes WHERE parent_id IS NULL AND type = 'folder'
```

This could return ANY folder with NULL parent, not specifically the repo root (which has is_repo_root = 1 in data).

**Fix**: Changed query to use is_repo_root flag:
```sql
SELECT id FROM nodes WHERE type = 'folder' AND json_extract(data, '$.is_repo_root') = 1
```

**Data fix**: For existing vaults, run:
```sql
UPDATE nodes SET parent_id = '.'
WHERE parent_id IS NULL AND type = 'folder'
AND json_extract(data, '$.is_repo_root') IS NOT 1;
```
