# [x] Implement Visual Board Navigation Model (CURSOR_* actions) @km/_orphan #feature #P2

Implement the spatial/visual navigation model from specs/@km/board-navigation/md.

## Summary

Replace structural navigation (j/k = prev/next sibling) with visual navigation (j/k = visually up/down, which may cross tree structure).

**BREAKING CHANGE**: This changes hjkl behavior. j/k will now traverse visual order (entering children, crossing to parent) rather than just moving between siblings.

## Key Changes

### 1. treeReducer.ts - Add CURSOR_* action handlers

- CURSOR_DOWN: Next visible block below (may enter child, go to sibling, or exit to parent's sibling)
- CURSOR_UP: Previous visible block above (may go to prev sibling's last descendant, or parent)
- CURSOR_LEFT: Cross-column left (at card/item level uses title y-center matching)
- CURSOR_RIGHT: Cross-column right (same matching logic)

Edge cases:

- At board level: h/l are no-op
- At column level: h/l move between columns
- Empty target column: land on column header
- Folded nodes: skip their children

### 2. commandParser.ts - Add cursor_* commands

- cursor_up, cursor_down, cursor_left, cursor_right

### 3. shellExecutor.ts - Update key mappings

- h → CURSOR_LEFT (was MOVE_LEFT)
- j → CURSOR_DOWN (was MOVE_DOWN)
- k → CURSOR_UP (was MOVE_UP)
- l → CURSOR_RIGHT (was MOVE_RIGHT)
- Arrow keys: same as hjkl

### 4. Tests

- packages/@km/_orphan/tui-core/tests/treeReducer.test.ts - Unit tests for CURSOR_* actions
- apps/@km/_orphan/cli/tests/sh/keys.test.md - Integration tests for visual order traversal

### 5. Backwards Compatibility

- Keep MOVE_* and NAV_* actions as legacy aliases
- Existing code using structural navigation still works
- Only hjkl key bindings change

## Out of Scope (Future Work)

- EXTEND_SELECT_* actions (shift+hjkl) - tracked separately
- SHIFT_* actions (opt+hjkl for moving nodes) - tracked separately

## Acceptance Criteria
