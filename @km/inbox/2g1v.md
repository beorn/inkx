# [x] Board materialization: add= results as child nodes @km/_orphan #feature #P1 @dafff868

When sync evaluates add= rules, matched items should become actual child nodes of the section (not just links). This enables:

1. **Reordering** - Items can be reordered within the section
2. **Moving** - Items can be moved between columns
3. **Persistence** - Changes persist in the DB and can be written to FS

Current behavior:
- add= results stored as links in links table
- getChildren returns linked nodes
- File is NOT updated

Desired behavior:
- add= results become child nodes (with link_to pointing to source)
- Sync reconciles to avoid duplicates (check if already a child)
- Changes to child nodes sync back to source
- File updated with materialized items

Implementation approach:
1. After evaluating add= query, for each match:
   - Check if already a child (by link_to or content hash)
   - If not, create child node with link_to = matched_node_id
2. On sync, reconcile: remove children whose sources no longer match
3. Write materialized structure to filesystem

Depends on: Proper reconciliation logic to avoid duplicates
