# [x] Visual navigation broken after boardReducer migration @km/_orphan #bug #P1 @8da317b9

## Summary
Visual navigation in board TUI was broken - arrow keys used different commands than hjkl.

## Root Cause
The keybindings.ts had arrow keys mapped to different commands than hjkl:
- `j` → `cursor_next` (sibling navigation)
- `↓` → `cursor_down` (document traversal - WRONG)

Per docs/06-ui.md, j/↓ and k/↑ should behave IDENTICALLY (visual-to-structural model).

## Fix
Changed keybindings.ts to make arrows use the same commands as hjkl:
- `ArrowDown` → `cursor_next` (was cursor_down)
- `ArrowUp` → `cursor_prev` (was cursor_up)
- `ArrowLeft` → `cursor_left` (unchanged)
- `ArrowRight` → `cursor_right` (unchanged)

## Files Changed
- `packages/km-commands/src/keybindings.ts` - Fixed arrow key mappings
- `packages/km-commands/src/commands/navigation.ts` - Removed conflicting shortcuts
- `packages/km-board/tests/visual-navigation.test.ts` - Added comprehensive tests
- `packages/km-commands/tests/*.ts` - Updated tests to match new behavior

## Testing
All 461 board and command tests pass.

## Notes
- The `cursor_up`/`cursor_down` commands still exist and do document traversal (crosses tree levels)
- They're just not bound to any keys in the standard board view
- They could be useful for future tree/outline view modes
