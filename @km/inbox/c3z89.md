# [x] Incremental reconciliation — event-driven instead of full directory scan @km/_orphan #feature #P3 @claude:8f007ba9

Current watcher pipeline debounces 2s then does full directory stat() of every file (O(N) per change). For typical single-file edits this is wasteful. Use Chokidar's per-file events for targeted updates (O(changes)). Keep full scan as fallback for startup/large bursts. Deep research confirmed this is the next optimization after async pipeline (now shipped).
