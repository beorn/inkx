# [x] Code structure review: hoist helpers to bottom @km/_orphan #task #P3

Systematically review codebase to apply \"important logic first, details later\" pattern.

## Goal

Apply code structure principles from CLAUDE.md section 4:

- Main logic at top of functions
- Helpers after `return` (hoisted functions)
- Pure helpers at module level (bottom of file)

## Scope

Review files in priority order:

1. **High-traffic files** (used frequently, worth optimizing for readability):
  - `apps/km-tui/src/views/Board.tsx`
  - `apps/km-tui/src/keyboard-*.ts`
  - `packages/km-storage/src/vault.ts`
  - `packages/km-board/src/board.ts`
2. **Complex files** (>200 lines, many helpers):
  - Find with: `find apps packages -name "*.ts" -o -name "*.tsx" | xargs wc -l | sort -rn | head -20`
3. **Rest of codebase** (systematic sweep)

## Anti-patterns to fix

### Pattern 1: Helper defined before main logic

```typescript
// ❌ BAD
function processVault() {
  function validatePath(p: string) { /* ... */ }
  function loadDb(p: string) { /* ... */ }
  
  const path = validatePath(vaultPath);  // Main logic buried
  const db = loadDb(path);
  return { path, db };
}

// ✅ GOOD
function processVault() {
  const path = validatePath(vaultPath);  // Main logic first
  const db = loadDb(path);
  return { path, db };
  
  function validatePath(p: string) { /* ... */ }  // After return
  function loadDb(p: string) { /* ... */ }
}
```

### Pattern 2: Pure helpers inline instead of module-level

```typescript
// ❌ BAD - formatDate doesn't need closure, should be at module level
function Component() {
  function formatDate(d: Date) { return d.toISOString(); }
  return <Text>{formatDate(new Date())}</Text>;
}

// ✅ GOOD
function Component() {
  return <Text>{formatDate(new Date())}</Text>;
}

function formatDate(d: Date) { return d.toISOString(); }  // Bottom of file
```

### Pattern 3: Multiple layers of nesting

```typescript
// ❌ BAD - helpers defined in middle of logic
function Component() {
  const data = loadData();
  
  function transformItem(item) { /* ... */ }  // Interrupts flow
  
  const transformed = data.map(transformItem);
  return <List items={transformed} />;
}

// ✅ GOOD
function Component() {
  const data = loadData();
  const transformed = data.map(transformItem);
  return <List items={transformed} />;
  
  function transformItem(item) { /* ... */ }  // After main logic
}
```

## Exclusions

Do NOT move:

- Exported functions (they ARE the main purpose)
- Very short functions (1-3 lines) used once
- Type guards that need to be near types

## Success criteria

- Main logic of each function is readable without scrolling
- Helpers grouped at bottom (after return or end of file)
- No decrease in test coverage (run `bun run test:all` after changes)

## Implementation notes

- This is a refactor-only task (no behavior changes)
- Can be done file-by-file or package-by-package
- Consider using `git mv` for renames to preserve history
- Each commit should be a single file or small group of related files
