# [x] Evaluate removing command-bridge in favor of unified dispatch @km/_orphan #task #P1

command-bridge.ts exists to route actions between Board.tsx UI handlers and boardReducer. This creates maintenance burden (must update type guards for every new action) and silent failures. Research better architectures:

**Recent bug example**: ZOOM_OUTWARDS was added to both isTUIAction and isUIAction. Since isTUIAction is checked first, the action matched there but the switch had no case for it - silent failure. This layered type guard approach is error-prone.

**Current problems**:

1. isUIAction/isTUIAction/isBoardAction type guards must be manually kept in sync with switch statements
2. Adding a new action requires updating: types.ts union, command-bridge type guards, Board.tsx switch cases
3. No exhaustiveness checking - missing cases silently fall through
4. Overlapping categories (TUIAction is subset of UIAction) creates confusion

**Key requirement**: Unhandled actions should be caught at compile time (TypeScript), not runtime.

Options to evaluate:

1. **Action-handler map pattern**: Single object mapping action types to handlers
  ```typescript
  const actionHandlers: Record<CommandAction['type'], (action: CommandAction) => void> = {
    ZOOM_INWARDS: (a) => handleZoomInwards(),
    ZOOM_OUTWARDS: (a) => handleZoomOutwards(),
    // TypeScript errors if any action type is missing
  };
  ```
2. Exhaustive switch with `never` in default case
3. Single combined reducer with exhaustive handling
4. Action middleware that validates completeness

Consider:

- TypeScript exhaustiveness checking for safety (compile-time errors for missing handlers)
- Ease of adding new actions (single place to add handler)
- Debug visibility when actions aren't handled
- Current split: UI actions (dialogs, zoom) vs board actions (cursor, selection)
