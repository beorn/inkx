# [x] Worker watcher status reporting in TUI bottom bar @km/_orphan #feature #P2

## Problem
When using worker-based file watching, users have no visibility into:
- Whether the watcher is active/ready
- How many files are being watched
- Recent sync activity (files changed, reconciled)
- Any errors from the watcher

## Solution
Add status reporting from worker → main thread → TUI bottom bar

### Worker → Main Thread
Extend WorkerMessage to include status updates:
```typescript
type WorkerMessage =
  | { type: "status"; watchedFiles: number; pendingPaths: number; state: "starting" | "ready" | "syncing" | "idle" }
  | ... existing types
```

### Main Thread → TUI
SyncManager emits status events:
```typescript
syncManager.on("watcher-status", (status) => {
  // status: { watchedFiles, pendingPaths, state, lastSync }
});
```

### TUI Bottom Bar
Display in bottom bar (similar to vim statusline):
- `[W: 21k files]` - watcher active with file count
- `[W: syncing 3]` - actively syncing 3 paths
- `[W: off]` - watcher disabled
- `[W: error]` - watcher error state

## Implementation
1. Add status message type to watcher-worker.ts
2. Add periodic status emission (every 5s or on state change)
3. Add status tracking to WorkerWatcher
4. Forward status to TUI via tuiEvents
5. Add status display to bottom bar in Board.tsx
