# [x] Design: Generator-based TEA with gradual effect migration @km/_orphan #feature #P2

Explore generator/yield as alternative to tuple returns for TEA state machines, enabling a smooth four-level progression: Component (useState) → Shared (Zustand) → Actions (dispatch + reducer) → Pure (yield effects as data). Key ideas:

1. Generator reducers: `function* apply(state, op) { yield effect; return newState }` — isomorphic to `[state, effects]` tuple via collect()
2. Mixed effects: yield functions (thunks, escape hatch) OR data objects (testable, serializable) — convert gradually per-effect
3. Effect creators parallel action creators: factory functions returning typed data objects
4. Single Zustand middleware (tea()) handles both plain and generator reducers
5. Smooth upgrade path where each level changes exactly one thing

Review against docs/design/tea-state-machines.md for alignment/conflicts. The existing doc specifies `(state, op) → [state, effects]` tuple — generators are an alternative representation. Need to decide: tuple vs generator vs support both.
