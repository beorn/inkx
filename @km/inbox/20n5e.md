# [x] curswantY not sticky across columns with different scroll offsets @km/_orphan #bug #P1 @claude:1588825b

## Bug Description
When navigating right (l) from a card lower in a scrolled column, the cursor doesn't land on a card at the same Y position in the target column.

User report: "curswantY isn't sticky - when in cards view I cursor right from ObsidianPKM cursor goes up to the column but doesn't go back down to the right y-coord"

## Root Cause Hypothesis
The curswantY is stored as a screen Y coordinate, but when columns have different scroll offsets, the screen Y positions don't match the logical card indices.

If column A is scrolled so card 5 is at screen Y=10, but column B is NOT scrolled, column B's card 0 is at Y=3. The navigation looks for a card at Y=10 in column B, which might find a different card than expected.

## Possible fixes
1. Store curswantY as a logical card index ratio instead of screen Y
2. Ensure both columns are scrolled to similar positions before calculating Y
3. Use card index as fallback when Y-based navigation fails
