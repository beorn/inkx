# [x] InkX: Character doubling during incremental updates in ttyd @km/_orphan #bug #P2

## Problem
When running inkx examples through ttyd (web terminal), navigating with keyboard input causes visual corruption:
- Text appears doubled (e.g., "In Progress" shows as "In Progressss")
- Column headers get corrupted ("Done" becomes "Donene")
- Content bleeds across areas

The initial render is clean; corruption only appears after incremental updates.

## Investigation Done
1. Cursor tracking in `changesToAnsi()` was fixed (@km/_orphan/w5ya)
2. Overflow clipping in `pipeline.ts` was fixed (@km/_orphan/mlv9)
3. Unit tests of diff and cursor positioning show correct behavior
4. The ANSI output sequences appear correct when examined

## Possible Causes
- xterm.js in ttyd may have issues with certain ANSI sequences
- Race condition in React reconciler during rapid state updates
- Buffer state management issue during fast re-renders
- Terminal size mismatch between web client and server

## Reproduction Steps
1. Run `ttyd -W -p 7681 bun run example:kanban` in vendor/beorn-inkx
2. Open browser to http://localhost:7681
3. Press 'j' to navigate down
4. Observe text doubling and visual corruption

## Files to Investigate
- `vendor/beorn-inkx/src/scheduler.ts` - render batching and timing
- `vendor/beorn-inkx/src/output.ts` - ANSI generation
- `vendor/beorn-inkx/src/buffer.ts` - cell comparison logic
