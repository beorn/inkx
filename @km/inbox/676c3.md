# [x] Reactive state: Reactive<T> signals replacing Zustand+Jotai dual-source @km/_orphan #feature #P1 @claude:f47d1ff0

Replace @km/tui's dual-source-of-truth (Zustand store + Jotai atoms + 5 manual sync functions) with a signal-based Reactive<T> primitive.

## Core Design

A generic Reactive<T> wrapper (~20 lines, lives in inkx):

- Holds value + subscriber set
- Writing .value notifies subscribers only if value changed (Object.is)
- useReactive(r) hook via useSyncExternalStore

State authors choose which fields are reactive:

```ts
interface TreeState {
  cursor: Reactive<NodeId>              // reactive — UI subscribes
  nodes: Map<NodeId, Reactive<NodeData>> // per-node reactive
  folds: Map<NodeId, Reactive<boolean>> // per-node reactive
  operationLog: TreeOp[]                // plain — no subscribers
}
```

.apply() writes directly to reactive fields — no bridge, no sync layer:

```ts
case "select_node":
  state.cursor.value = op.nodeId  // 1 signal notifies, 2 components re-render
```

## What This Eliminates (~1500 LOC)

- board-app-store.ts (Zustand store, 1107 LOC) → TEA machines
- node-atoms-hydrate.ts (5 sync functions, 216 LOC) → gone
- cursor-store.ts (hand-rolled pub/sub, 204 LOC) → gone
- Jotai dependency → gone (Reactive<T> replaces it)
- Zustand dependency → gone

## What Survives

- Per-node atom structure from node-atoms.ts → becomes Map<NodeId, Reactive<NodeData>>
- VirtualList limiting mounted nodes to ~30-50 visible

## Automerge Integration

- Local edits: .apply() writes signals + Automerge.change()
- Remote edits: CRDT patches → targeted signal writes
- Both paths converge on same Reactive<T> updates

## Performance

- Cursor move: 2 signal notifications (~0.1ms)
- Node edit: 1 signal notification
- All visible nodes subscribe to cursor signal — 50 re-evaluations, 49 bail out, 2 re-render

## Alternatives Considered

1. One big atom + derived atoms → O(n) recomputation per change (Jotai marks all derived stale)
2. Operation-targeted dispatch bridge → works but adds a manual switch statement layer
3. SlateJS selector pattern (useSlateSelector) → O(subscribers) per change vs O(affected) for signals
4. Atom-and-value pairs → isomorphic to signals but needs reconciler
