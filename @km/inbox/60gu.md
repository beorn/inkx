# [x] Implement unified action flow for TUI mutations @km/_orphan #feature #P2

## Summary

Refactor TUI to use TAction for all content mutations, creating a consistent command/data flow pattern that supports keyboard, command palette, and CLI.

## Current State

- Navigation (hjkl): Command → BoardAction → boardReducer ✓
- Data mutations (x, d, tab): Direct storage.updateNode() calls ✗
- TAction is defined but never dispatched
- No formal command registry

## Target State

```
User Input (key, click, or command palette)
    ↓
Command Registry (maps input → command name)
    ↓
Action Creator (command → typed action)
    ↓
dispatch(action)
    ↓
Reducer Chain (App → Board)
    ↓
Effect Layer (handles side effects)
    ↓
Storage (SQLite + file sync)
```

## Key Design Decisions

### Action Naming

Actions use simple names without prefixes: `UPDATE_NODE`, `DELETE_NODE`, `ADD_NODE`, `MOVE_NODE`.
(Previously had `T_` prefix which was removed for consistency.)

### Idempotency

Actions are idempotent (set to a value, not toggle). Toggle logic belongs in commands:

- Command: `toggle_task_done` reads state, computes target value
- Action: `{ type: 'UPDATE_NODE', updates: { task_status: 'done' } }`

### Parameterized Actions

Use parameterized actions instead of many specific actions:

- `CURSOR_MOVE { dir: 'up' | 'down' | 'left' | 'right' }` instead of separate CURSOR_UP, etc.

## Implementation Steps

### Phase 1: Command Registry

1. Create `@km/commands` package with command definitions
2. Each command: name, description, action creator function
3. Commands are UI-agnostic (same registry for TUI, CLI, future web)

### Phase 2: Effect Layer

4. Create effect layer in useAppState.ts that watches for TActions
5. Effect layer calls storage.updateNode() when TAction dispatched

### Phase 3: Refactor Handlers

6. Refactor x/d/tab handlers in App.tsx to:
  - Look up command in registry
  - Create action via command's action creator
  - dispatch(action)

### Phase 4: Undo Support

7. Add TActions to UNDOABLE_ACTIONS set for undo/redo support

## Benefits

- **Command palette ready**: Commands are discoverable and searchable
- **Customizable keybindings**: Keys map to commands, not code
- **Undo/redo**: All actions tracked in history
- **Consistent pattern**: Same flow for navigation AND mutations
- **Multi-window sync**: Actions can be broadcast
- **Testable**: Pure commands and reducers
