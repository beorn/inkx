# [x] Level 3: Centralize key handling in createApp() term:key handler @km/tui #task #P2

Move ALL key handling from useInputLayer to createApp() centralized term:key handler.

## Current State (after L2)
- Board state in Zustand store via createApp()
- Keys still flow through useInputLayer → command bridge → command system
- InputLayerProvider still manages input dispatch

## Target
- createApp() term:key handler receives ALL keys before React
- Handler calls processKeyWithContext → command system → when predicates → action
- Actions update Zustand store via set()
- React re-renders via useApp(selector) subscriptions
- No useInputLayer, no InputLayerProvider needed

## Key Flow
```
stdin → TermProvider → term:key event → createApp handler
  → processKeyWithContext → @km/commands (when predicates)
  → action → set() Zustand store
  → React re-renders via useApp(selector)
```

## Dialog Input
Dialogs (search, new item, project picker) handled via when predicates:
- `when: textInputFocused` routes to TextEditTarget
- `when: isInlineEditing` routes to inline edit
- Dialog-specific keys (Escape, Enter) use dialog-specific predicates
- No per-dialog useInputLayer handlers needed

## Advantages
- Keys handled before React render cycle
- Single entry point for all input
- No race conditions from async useEffect registration
- Testable: driver.press() → term:key → same path as live app
- AI introspection: app.getState() gives full picture

## Files to Modify

- `apps/km-tui/src/views/Board.tsx` — remove useInputLayer
- `apps/km-tui/src/views/SearchDialog.tsx` — remove useInputLayer, rely on when predicates
- `apps/km-tui/src/views/ProjectPicker.tsx` — same
- `apps/km-tui/src/views/NewItemDialog.tsx` — same
- `apps/km-tui/src/tui.tsx` — remove InputLayerProvider wrapper
