# [x] Level 1: Board useInput → useInputLayer migration @km/tui #task #P2

Migrate Board.tsx from direct useInput to useInputLayer("board") as the base input layer.

## Current State

- Board.tsx line 872 uses `useInput()` directly for ALL key handling
- Dialogs (SearchDialog, ProjectPicker, NewItemDialog) already use `useInputLayer()`
- InputLayerProvider wraps BoardApp in tui.tsx line 192
- Board's useInput and dialogs's useInputLayer coexist but Board bypasses the layer stack

## Problem

Board's `useInput` fires independently of the InputLayerProvider stack. When a dialog is open, BOTH the dialog's useInputLayer handler AND Board's useInput fire, causing potential double-handling.

## Target

- Board uses `useInputLayer("board", handler)` as the base layer
- Handler returns `true` to consume (always — Board is the bottom layer)
- Dialogs consume keys before Board via stack ordering
- Single unified input path through InputLayerProvider

## Files to Modify

- `apps/km-tui/src/views/Board.tsx` — `useInput` → `useInputLayer`
- `apps/km-tui/src/views/board-input.ts` — handler returns boolean (consumed?)

## Testing

- Existing driver tests should pass unchanged
- Verify dialogs consume keys (escape, typing) without Board also handling them
